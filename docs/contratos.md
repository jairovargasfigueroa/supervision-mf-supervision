# ERP · Microfrontend Supervisión: contratos

**Estado:** lo de abajo es lo conocido; las operaciones exactas se definen en el `diseno.md` de cada funcionalidad.

## Consume

- Gateway GraphQL (`docs/contratos/graphql-erp.md` de la carpeta general), con `Authorization: Bearer <token>` del shell:
  - `tablero` (009) en `src/tablero/tablero.graphql.ts`: `indicadores { obrasEnEjecucion obrasEnRiesgo materialesBajos cobrosVencidos { cantidad monto } }` y `obras { obraId nombre avancePct plazoPct diferencia enRiesgo materialesBajos ultimaPlanilla { periodo estado } }`. Se pide con `errorPolicy: 'all'`: un campo en `null` con `SERVICIO_NO_DISPONIBLE` se muestra «—» con «Datos de {servicio} no disponibles» (el servicio sale de `extensions.servicio` o, si no viene, del dueño del campo: Obras, Materiales o Finanzas). `cobrosVencidos` llega en `null` sin error para roles que no son `admin` ni `gerente`: para ellos la tarjeta no se muestra.
  - 402, en la misma consulta `tablero`: `indicadores.obrasRiesgoAlto` (tarjeta «Riesgo alto (modelo)») y `obras.riesgoRetraso { probabilidad nivel factores { variable descripcion peso } versionModelo calculadaEn }` (columna «Riesgo (modelo)», ordenable: chip `BAJO` verde, `MEDIO` amarillo, `ALTO` rojo, `SIN_DATOS` gris «Sin datos», y porcentaje entero). Si IA no responde, esos campos llegan en `null` con `SERVICIO_NO_DISPONIBLE` (`extensions.servicio = "ia"`) y se muestran «—» con «Datos de IA no disponibles». La columna «Riesgo» (regla «En riesgo») se mantiene.
  - 402, pantalla «Riesgo de retraso» (`/supervision/riesgo`, en `src/riesgo/riesgo.graphql.ts`): la lista usa la misma consulta `tablero` (ordenada por `riesgoRetraso.probabilidad`, de mayor a menor; sin datos o sin IA al final); al elegir una obra, `obra(id) { id historialRiesgo(limite: 30) { probabilidad calculadaEn } }`; y el panel «Sobre el modelo», `modeloRiesgo { versionModelo entrenadoEn datos filasEntrenamiento metricas { aucRoc aucRocRegla recallMedio precisionAlto brier } umbralMedio umbralAlto }`. Las dos con `errorPolicy: 'all'` y respaldo de la 104. `historialRiesgo` o `modeloRiesgo` en `null` con error → «—» con «Datos de IA no disponibles»; `MODELO_NO_DISPONIBLE` → «El modelo de riesgo no está disponible por el momento.». El aviso del panel depende de `datos`: `SINTETICOS` → «Modelo entrenado con datos sintéticos; es una estimación de apoyo, no reemplaza la revisión de la obra» (con la advertencia de que las métricas no prueban que acierte con obras reales); `REALES` → «Modelo entrenado con datos reales; es una estimación de apoyo, no reemplaza la revisión de la obra».
  - 403, en la misma consulta `tablero`: `indicadores.consumosAtipicosPendientes` (tarjeta «Consumos atípicos por revisar») y `obras.consumosAtipicosPendientes` (columna «Atípicos», ordenable; al pulsar la fila, también el número, se abre `/obras/:id`). IA caída: `null` con `SERVICIO_NO_DISPONIBLE` → «—» con «Datos de IA no disponibles» (el aviso de la tabla sale una sola vez aunque falten el riesgo y los atípicos).
  - 503, pantalla «Reportes» (`/supervision/reportes`, solo `admin` y `gerente`; en `src/reportes/reportes.graphql.ts`): `catalogoReportes { conjuntos { conjunto titulo descripcion columnas { clave titulo tipo } filtros agrupaciones ejemplos } atajos { atajo titulo descripcion } }` y `consultasReporte(limite: 10) { id texto atajo conjunto resultado resumen totalFilas creadaEn }` (con el respaldo de la 104), y la mutación `consultarReporte(texto | atajo) { id texto atajo conjunto tituloConjunto aplicado { nombre valor } resumen resumenPlantilla avisos columnas { clave titulo tipo } filas totalFilas truncado creadaEn }` (exactamente uno de `texto`, de 3 a 500 caracteres, o `atajo`). Errores en `extensions.codigo`: `INTENCION_NO_RECONOCIDA` y `RECETA_INVALIDA` → «No encontré un reporte para tu pedido» con los conjuntos, sus ejemplos y los reportes comunes; `TEXTO_INVALIDO`; `DEMASIADAS_CONSULTAS`; `LLM_NO_DISPONIBLE` (con la sugerencia de usar los reportes comunes), `REPORTES_NO_DISPONIBLES` y `SERVICIO_NO_DISPONIBLE` → «El servicio de reportes no está disponible; intenta de nuevo»; `TIEMPO_AGOTADO` o 60 s sin respuesta → «El reporte tardó demasiado; intenta de nuevo». El texto se pide con el `CampoDictado` de la 302 (al gateway solo llega el texto). Exportación a Excel (hojas «Datos» y «Consulta») y CSV (UTF-8 con BOM) en el navegador con SheetJS 0.20.3; los textos que empiezan con `=`, `+`, `-` o `@` llevan un apóstrofo delante.
  - En las capas 4 y 5: predicciones, agentes, sugerencias y reportes por voz.
- 302: modelo Whisper `onnx-community/whisper-base` (pesos `q8`) desde Hugging Face (o desde la ruta de `DICTADO_MODELO_URL`, variable de compilación; `DICTADO_MODELO=onnx-community/whisper-tiny` para equipos lentos), descargado por el navegador y guardado con la Cache API. El motor de onnxruntime-web (`.wasm`) lo trae transformers.js de su CDN (jsDelivr), su valor por defecto. El audio no sale del navegador.
- Shell: sesión del usuario en `window.plataforma.sesion` (token con `obtenerToken()`, roles en `usuario.roles`) y URL del gateway en `window.plataforma.configuracion.gatewayUrl`.
  - 104: `sesion.sinConexion` (en ese modo `obtenerToken()` rechaza con `Error('SIN_CONEXION')`), `window.plataforma.conexion` (`{ enLinea, reportarFallo() }` y el evento `plataforma:conexion` con `detail: { enLinea }`) y `window.plataforma.almacen` (`guardarConsulta`, `leerConsulta`; separado por usuario). Si no existen (microfrontend abierto solo), trabaja en línea y sin guardar nada.

## Expone

- Web Component cargado por Native Federation (`./Bootstrap` registra la etiqueta), montado por el shell en su ruta `/supervision/**`.
- 302, dentro del microfrontend: componente `CampoDictado` en `src/dictado/` (texto editable + micrófono), que usa la pantalla «Reportes» de la 503. El worker de Whisper se publica como `whisper.worker.js` junto al código del microfrontend; dentro del shell se crea con un worker local (`blob:`) que lo importa (un worker no puede venir de otro origen; el servidor del microfrontend tiene CORS abierto).
- Navegación hacia el shell: al pulsar una obra del tablero cambia la dirección a `/obras/:id` con `window.history.pushState` y emite `popstate`; el router del shell abre el detalle de la obra en el área Obras (009, criterio 4).
